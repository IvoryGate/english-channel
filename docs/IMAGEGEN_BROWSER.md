# Browser Image Generation

## Purpose and Boundary

Covers, Shorts backgrounds, and show art are generated by driving the **web
ChatGPT image tool through a browser** (the pathway proven by vibecut and
ported here). There is no image API key and no API-based tool.

Hard rules that never change:

- The image model only paints **textless backgrounds**. Layout text
  (episode number, title, captions) is composited deterministically in
  code by `workspace/shows/tools/render_episode_thumbnail.py` (or the
  Shorts pack renderer) to prevent spelling drift.
- The browser performs **generation only**. Login is a one-time human
  step per profile; any account-level or bulk write operation stays
  behind the authority gate and is out of scope for these scripts.

## Session Workflow

The session is started once per working day and closed at end of day:

```powershell
# Start (persistent Chromium + CDP on port 9334; opens a blank tab — the
# first generate call navigates to ChatGPT itself)
python apps/worker-py/scripts/imagegen_session.py

# ...log in once in that window if prompted (first day / expired session)...

# Generate (attaches over CDP, never opens its own window)
python apps/worker-py/scripts/generate_image.py --prompt "..." --out "path/to/image.png"
python apps/worker-py/scripts/generate_image.py --prompt-file prompt.txt --out "..." --chat new

# End of day: Ctrl+C in the session terminal
```

Key facts:

- Login state persists in `workspace/runtime/imagegen/chromium-profile/`
  (inside the ignored `workspace/` tree; nothing to commit, nothing for
  the encoding gate).
- CDP port defaults to **9334** (`EN_CHANNEL_CDP_PORT` overrides), chosen
  so it cannot collide with a vibecut session on 9333. The profile dir is
  overridable with `EN_CHANNEL_PROFILE_DIR`.
- Attach mode fails loudly if the session is missing or the login expired
  — it never silently opens a browser.
- `--standalone` launches a one-off browser (owns its lifecycle) for the
  first login on a new machine.
- `--chat` controls conversation hygiene: `new` (default, fresh
  conversation per generation), `continue`, or a conversation `<URL>` to
  iterate variants of the same scene in one thread.

## Anti-Fingerprint Rules

The site is a consumer product; the automation must not look like a bot.
These rules are enforced in `apps/worker-py/worker/imagegen/chatgpt.py`
and must survive any refactor:

1. Real browser window only — headed Chromium, bundled engine preferred,
   default user agent, no Playwright automation flags, no ad blocker.
2. Never drive the DOM directly: no injected send-button clicks, no
   `page.fill`; text goes through real keystrokes (`locator.type`).
3. Segment input into 5–13 character chunks with 30–85 ms per-character
   delays and 0.06–0.28 s pauses between chunks.
4. Randomness comes from `secrets.SystemRandom()` (system entropy) with
   **no fixed seed anywhere** — chunk sizes, delays, and pauses are never
   reproducible.
5. The input-to-submit pause is 2.5–6.5 s of real sleeping.
6. On a challenge page: stop, back off 8–16 s multiplied by the attempt,
   click the site's own retry control, at most 2 retries.
7. The session browser stays open between tasks; repeated attach runs
   share one conversation context instead of spawning windows.
8. Exactly one image per prompt; the newest image in the conversation is
   the one extracted (never an older one in a multi-image thread).

## Output And Traceability

`--out <path>` writes the image plus `<path>.meta.json`:

```json
{
  "prompt": "...",
  "mime": "image/png",
  "size": 123456,
  "sha256": "...",
  "chat_url": "https://chatgpt.com/c/...",
  "send_pauses_sec": [4.37],
  "generated_at": "2026-10-07T14:02:11+08:00"
}
```

The `sha256` ties the delivered file to the generation event; the
`chat_url` makes iterations auditable. Keep these sidecars next to the
media they describe (media itself stays untracked, as with all generated
audio/video).

## Integration With The Pipeline

Episode cover (`docs/shows/VIDEO_PIPELINE.md`):

1. `workspace/shows/tools/render_episode_thumbnail.py --print-prompts`
   emits the 16:9 scene prompt (with any conflicting text stripped).
2. Feed that prompt to `generate_image.py --out` on the episode's
   `scene_source` path.
3. `render_episode_thumbnail.py --from-scene ...` normalizes the file and
   overlays the code-drawn text.

Shorts backgrounds: each item's `visualBrief` in the weekly config is the
prompt; generate to `background.png` under the week's `public/shorts/`
directory (untracked), then run the pack renderer.

## Known Limits

- Selectors target the **zh-CN** ChatGPT UI (the session launches with
  `--lang=zh-CN`). A UI redesign or locale change breaks them loudly —
  update the selector constants at the top of `chatgpt.py`.
- Generation waits cap at 4 minutes per image; challenges at 2 retries.
- CI never opens a browser: unit tests cover only the pure logic
  (chunking, jitter bounds, mime mapping, argument parsing, CDP probes).
